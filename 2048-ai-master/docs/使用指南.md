# 2048 AI 使用指南（冲分规范）

> 另见 [`实战经验.md`](实战经验.md)：仓库检修记录 + 2048verse.com 真实网站
> 接入方法（CDP 驱动、踩坑修复、16384 实战数据）。

本文档说明如何用本仓库的 AI **高效合成 2048 以及更大的数字**（4096 / 8192 /
16384 / 65536，5-bit 表示上限 2^31）。全程分三步：**构建 → 选择使用方式 → 按规范操作**。

---

## 1. 构建（一次性）

```sh
# 方式一：自动工具链（需要 autoconf/automake）
./configure && make

# 方式二：快速编译（macOS/Linux，无需 autotools）
mkdir -p bin
g++ -O3 -Wall -Wextra -fPIC -shared -o bin/2048.so 2048.cpp   # Python 绑定用
g++ -O3 -o bin/2048 2048.cpp                                  # 命令行自走棋
```

Windows 见根目录 `README.md` 的 MinGW / Visual Studio 小节。注意 Python 与
DLL 的**位数必须一致**（32 位对 32 位、64 位对 64 位）。

---

## 2. 三种使用方式

### 方式一：命令行自动对局（最省心、最快）

```sh
bin/2048
```

AI 自己玩，逐步行打印搜索统计（评估节点数、缓存命中、耗时），结束时报告
最终分数和最高方块。**想冲大数字但不想动手，就用这个。**

### 方式二：浏览器自动控制（真实网页上演示）

```sh
# Chrome（先按 README 用远程调试参数重启 Chrome）
python3 2048.py -b chrome -p 9222
# Firefox（先开启远程调试并 --start-debugger-server 32000）
python3 2048.py -b firefox -p 32000
```

可选 `-k keyboard|fast|hybrid|play2048co` 切换对网页的兼容模式（默认
`hybrid`）。多线程数用环境变量调：`2048_THREADS=8 python3 2048.py ...`。

### 方式三：交互式教练模式（学打法、手机/平板上用）

```sh
python3 2048.py -b manual
```

- 逐行输入当前棋盘（空格分隔，如 `16 128 256 1024`）；
- AI 给出推荐方向（up / down / left / right）；
- 你执行后，把**新生成的方块**告诉 AI：`行,列,值`（1 起始），如 `3,1,4`；
- 多个更新写一行：`1,1,4 1,3,2`。

> 输入的数值只支持 0 或 2 的幂（2、4、8、…、2^31），输入别的会提示重输。

## 3. 使用规范：如何高效合成 2048 及更大数字

### 3.1 核心原则：角落策略（Corner Strategy）

AI 的启发式（空位奖励、单调性惩罚、合并奖励）本质就是编码了经典角落策略。
**你手动玩时照抄这套规范，就能稳定过 2048：**

1. **把最大方块钉死在角落**（推荐左下角）。
   - 之后**永远不要**让它离开角落：只按 `←`（左）和 `↓`（下）作为主力方向。
   - `↑`（上）和 `→`（右）只在**迫不得已**（不按就死）时用一次，用完立刻
     把大块拉回角落。
2. **沿两条边构建单调递减链**：第二大块紧贴大块旁边，第三大块再接下去
   （例如左下角是 1024，左边缘依次 512、256、128）。
3. **优先在"尾部"（远离大块的两行）做合并**，保持大块区域干净：
   - 小数字（2、4）不要溜进大块所在的行/列；
   - 尽量保持整盘没有孤立的单格空位（空格越整齐，越不容易死）。
4. **不要为了分数贪多步**：每一步都以"维持链条 + 清出空格"为目标，而不是
   追着能合并的数字跑。

### 3.2 用 AI 当教练（推荐流程）

- 开局后每步都问 AI：`python3 2048.py -b manual`，输入棋盘 → 执行 AI 的
  建议 → 回报新方块 → 再问下一步。
- 这样玩 10~20 局，你会自然内化"什么时候该牺牲一步、什么时候必须换方向"。
- 遇到"AI 建议的方向和你直觉相反"，先照 AI 做，再复盘：通常它是在为
  后面 2~3 步的链条铺路。

### 3.3 AI 的工作原理（帮你理解它为什么这么下）

- **搜索**：expectimax（对每个方向，枚举新方块落在每个空格，2 与 4 的概率
  按 0.9 / 0.1 加权），配转换表缓存，深度自适应
  `max(3, 不同方块种类数 − 2)`——盘面越丰富，AI 看得越深。
- **启发式权重**（`2048.cpp` 中可改）：
  - 空位奖励 `SCORE_EMPTY_WEIGHT = 270`
  - 可合并奖励 `SCORE_MERGES_WEIGHT = 700`
  - 单调性惩罚 `SCORE_MONOTONICITY_WEIGHT = 47`（幂 4）
  - 总和大惩罚 `SCORE_SUM_WEIGHT = 11`（幂 3.5）
  - 死亡惩罚 `SCORE_LOST_PENALTY = 200000`
  - 直观结论：**空位 > 可合并 > 单调性 > 贪分数**。

### 3.4 硬件与理论极限

- 速度：现代 CPU 上每秒可评估上千万步（本机实测约 5 千万步/秒，单步
  0.04 秒内完成深达 7 层的搜索）。
- **表示上限**：每个格子 5 bit 存"指数 rank"，最大可表示方块为
  **2^31**（rank 31）。因此 2048、4096、8192、16384、**65536、131072**
  都完全支持；两个 rank 31 相遇视为不合并。

### 3.5 加速旋钮（想更快就调这些环境变量）

| 环境变量 | 作用 | 实测 |
| --- | --- | --- |
| `2048_DEPTH=-3` | 搜索深度 -3（更浅更快） | ~5× 加速 |
| `2048_CPROB=0.001` | 剪枝阈值提高到 1e-3 | ~8× 加速 |
| 两者组合 | | ~16× 加速 |
| `2048_KEY_DELAY=0.02` | 浏览器按键落定延迟（默认 0.05s） | 对局更快 |
| `2048_THREADS=8` | 浏览器控制线程数 | 多核加速 |

用法：`2048_CPROB=0.001 2048_DEPTH=-3 python3 2048.py -b chrome`
（代价：深度/剪枝激进时 AI 变弱，冲大数字建议保持默认）。
- 想冲 16384+ 级别：保持机器空闲、浏览器模式用满线程
  （`2048_THREADS=8`），必要时重新编译时调大 `CACHE_DEPTH_LIMIT` /
  降低 `CPROB_THRESH_BASE` 以加深搜索（会显著变慢）。

## 4. 常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到 `bin/2048.so` | 先构建（见第 1 节），再运行 |
| Chrome 报 websocket 错误 | `pip install websocket-client` |
| 浏览器连不上 | 按 README 用 `--remote-debugging-port` + `--remote-allow-origins` 重启浏览器 |
| 加载 DLL 报 Win32 错误 | Python 与 DLL 位数不一致，重新编译对应位数 |
| 一直到不了 2048 | 属正常波动，重开一局；或用教练模式学习角落策略 |

---

## 5. 快速上手（TL;DR）

```sh
./configure && make          # 或快速编译一行
bin/2048                     # 直接看 AI 冲分
python3 2048.py -b manual    # 问 AI 该怎么走（手机也能用）
```

**冲分口诀**：大块锁角落，链子沿边排，小字往后推，空位不乱留。
