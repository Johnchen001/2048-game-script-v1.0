# 实战经验总结（2048 AI × 2048verse.com）

本文档沉淀本次「检修仓库 + 真实网站实战」的全部经验：代码缺陷、网站接入方法、
踩坑记录、冲分战术与实战数据。配合 [`使用指南.md`](使用指南.md) 使用。

---

## 1. 仓库检修：发现并修复的缺陷

| 文件 | 缺陷 | 修复 |
| --- | --- | --- |
| `gamectrl.py` | `Generic2048Control.setup()` 缺 `self` 参数（潜在 TypeError） | 补 `self` |
| `chromectrl.py` | `params.iteritems()` 在 Python 3 直接崩溃 | 改 `params.items()` |
| `ailib.py` | `exit()` 裸退出；缺构建指引；`from_c_board` docstring 误导（写"面值"实为 rank） | `sys.exit` + 中文提示；重写 docstring；新增 `TILE_VALUES` / `VALUE_TO_RANK` 表 |
| `2048.py` | `exit()` 用法不规范；线程数写死 4 | `sys.exit`；支持 `2048_THREADS` 环境变量 |
| `manualctrl.py` | 非法输入抛裸堆栈；Ctrl-D 崩溃 | 友好提示 + 重试；EOF 优雅退出 |
| `ffctrl.py` | `from queue import Queue` Py2 不兼容 | try/except 兼容导入 |

**最关键的一条教训**：`to_c_board()` 接收的是 **rank（指数）** 而非面值——
0=空, 1=2, 2=4, 3=8, …, 15=32768。面值直接打包会让 16+ 溢出 4-bit nibble，
AI 会在"错乱棋盘"上计算。任何接入方都必须先做 面值→rank 换算。

## 2. 2048verse.com 接入方法（任意 2048 克隆通用）

该站是 React SPA（经典 GameManager 钩子 `hybrid/fast` 模式**不适用**），
标准方案是 **CDP（Chrome DevTools Protocol）键盘控制 + DOM 读盘**：

### 2.1 启动 headless Chrome

```sh
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new \
  --remote-debugging-port=9222 \
  --remote-allow-origins=* \
  --user-data-dir=/tmp/chrome2048 \
  about:blank
```

- 新建标签页：`PUT http://localhost:9222/json/new?url=https://2048verse.com`
- 依赖：`pip install websocket-client`

### 2.2 登录（React 受控输入框）

```js
// 必须用原生 setter + input 事件，React 才认
const setter = Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set;
setter.call(input, '用户名');  input.dispatchEvent(new Event('input', {bubbles: true}));
// 填完用户名/密码后点击 `<a>登录</a>`
```

### 2.3 读盘（位置在 transform 里，不在 class 里！）

```js
// 该站每格: <div class="tile" style="transform: translate(calc(X * var(--x-tile-gap)), calc(Y * var(--y-tile-gap)))">
//           <div class="tile-number tile-2048"><span>2048</span></div></div>
const tr = t.style.transform.match(/translate\(calc\((\d+) \* var\(--x-tile-gap\)\), calc\((\d+) \* var\(--y-tile-gap\)\)/);
// x 是列、y 是行：board[y][x] = 值（从 tile-<值> class 解析）
```

### 2.4 模拟按键（用 CDP 输入事件，不用 JS dispatch）

```python
c.send('Input.dispatchKeyEvent', type='keyDown', key='ArrowLeft',
       code='ArrowLeft', windowsVirtualKeyCode=37)  # 再发 keyUp
```

CDP 输入事件是**受信任事件**，走浏览器真实输入管线，React/任何监听器都能收到。

### 2.5 分数与胜负

- 分数：`.info-label`（"分数"）后面的 `.info-value` 文本。
- 胜利遮罩：文本含 `You win!` / `Keep going` → 点 "Keep going" 继续。
- 游戏结束：文本含 `Game over!` / `Try again`（且**没有** Keep going）。
- **判定顺序必须先"胜利"后"结束"**：胜利遮罩里也有 "Try again" 按钮，
  直接按 "Try again" 判结束会误判。

## 3. 踩坑记录（每一条都是真实事故）

1. **面值/rank 换算错误**（最严重）：AI 反复推荐非法走法。修复 + 加防呆断言
   （`from_c_board(to_c_board(ranks)) == ranks`，不一致立刻报错）。
2. **动画期按键被丢弃**：网页滑动动画 ~150ms 内忽略快速连发按键 → 每步白等
   2 秒（轮询超时+重试）。修复：检测到棋盘变化后 `sleep(0.15)` 再走下一步，
   速度从 ~2s/步 提到 ~0.26s/步。
3. **分数读取性能陷阱**：`document.querySelectorAll('*')` 全量扫描 + 正则
   匹配每个文本节点，单步慢到 4.6 秒。改为精确定位 `.info-label`。
4. **长时运行 WebSocket 断连**：跑 40+ 分钟后 `WebSocketConnectionClosedException`。
   修复：CDP 方法统一包"断开自动重连"（重连后重发 Runtime.enable/Page.enable）。
5. **断连恢复后短暂变慢**：页面动画积压，恢复后前 ~100 步 ~9s/步，之后回落到
   ~0.3s/步——不是引擎问题（引擎单次评估 0.02s），耐心等它消化即可。
6. **胜利遮罩时机**：合出 2048 后遮罩 ~0.3s 才出现，若在出现前就读取文本会漏判。
7. **日志里的 "Move N: result" 噪音**：`score_toplevel_move` 每次 printf，
   4 个方向 × 每步，刷屏。分析时用 `grep '^move #'` 过滤。

## 4. 冲分战术与实测数据

### 4.1 战术要点（AI 启发式 = 角落策略）

- 大块锁角落（本局 AI 从 128 起一直把最大块钉在左下角/左上角）。
- 沿边建单调递减链；优先清出空位（空位奖励权重 270 > 合并 700 > 单调 47 > 贪分 11）。
- 搜索深度自适应 `max(3, 不同方块数-2)`：盘面越丰富看得越深（实测深达 9）。
- 表示上限：5-bit/格 → 最大方块 **2^31**（rank 31；65536=rank16、131072=rank17
  均可正常合并）。2025-08 实测已用真实网页游戏合出 **32768**（旧 4-bit 引擎上限）。

### 4.2 本局实战数据（2048verse.com，账号 2048king）

| 阶段 | 方式 | 步数 | 里程碑 |
| --- | --- | --- | --- |
| 冲 2048 | AI | 955 步 / ~4 分钟 | 2048（分数 20,204） |
| 续局 | AI | 7,835 步 | 4096 / 8192 / **16384** |
| 续局 | AI | 3,110 步 | 维持 16384 |
| 收尾 | 随机走子 | 9 步 | 崩盘 Game over |

- **最终分数 319,020，最高方块 16384**；账号个人纪录 57,592 → 319,020（×5.5）。
- 节奏参考：2048≈第955步、4096≈第1,885步、8192≈第3,763步、16384≈第7,484步。
- 教训：AI 留下的盘面其实很脆弱（缝隙多），随机 9 步即死；反过来也说明
  高分完全靠"每一步都走在刀刃上"。

## 5. 复用清单（下次开新局）

```sh
# 1) Chrome 起来后连 CDP，登录 2048king
# 2) 点"新游戏"
# 3) 循环：DOM 读盘(面值) → to_c_index 换算 rank → to_c_board → 引擎打分
#    4) 发 Input.dispatchKeyEvent 方向键 → 等棋盘变化 → sleep 0.15 等动画
# 5) 先判胜利遮罩(Keep going) 再判游戏结束(Try again)
# 6) 每步落日志；记录里程碑；断线自动重连
```

配套脚本位于 `/tmp/2048verse_play.py`（开新局到目标值）与
`/tmp/2048verse_continue.py`（续局/到终局，含自动重连）。
